# Agent Note：Windows 安装器 E2E 路径身份

状态：已实施

[English](2026-09-14-windows-installer-e2e-path-identity.md) | 中文

## 问题

Windows 可以通过 8.3 短名称路径和长名称路径暴露同一个普通目录。Windows 托管运行器的临时用户目录会采用这种形式。安装器 E2E 安全检查此前要求 `realpath()` 文本与 `path.resolve()` 文本相同，因此路径拼写规范化会被误判为 junction。应用即使成功安装，也无法进入就绪验证，测试夹具清理同样会被拒绝。

测试必须接受指向同一普通目录的不同路径拼写，同时不能削弱递归清理前对 junction 穿越的保护。

## 决策

安装器测试夹具根目录和运行时包根目录通过 `lstat()` 逐级检查每个已存在的路径组件。每个组件都必须是普通目录，并且不能是符号链接或 junction。系统不再把 `realpath()` 与输入路径拼写的文本相等作为身份判断条件。

每个已注册的运行时包根目录同时保留经过验证的词法拼写和物理 `realpath()` 拼写。Windows 扩展命名空间前缀会在包含关系检查时被规范化。只有当生成的回退 junction 的原始目标和现存物理目标都位于这些已注册表示之一时，系统才会接受它；目标缺失时仍然必须具有词法注册证据。

经过认证的所有权标记、所有权环境值、子路径包含关系、递归后代检查和已注册回退目标检查仍然是必需条件。通过任意 junction 祖先到达的路径，在注册或递归删除前都会被拒绝。

## 验证

安装器支持测试覆盖普通夹具根目录、未注册的后代 junction、已注册的生成回退 junction、等价的普通目标拼写和扩展命名空间目标拼写，以及通过 junction 祖先到达的运行时包根目录。Windows 托管安装器冒烟测试会使用 8.3 临时目录拼写，并验证清洁安装、已打包应用就绪、离线启动、关闭和清理。

## 考虑过的替代方案

**忽略大小写比较规范化字符串。** 短名称和长名称别名的路径组件并不相同，因此这种方式仍会拒绝有效别名。

**删除物理路径检查且不提供替代保护。** 这会允许 junction 祖先把递归清理重定向到经过认证的夹具之外。

**对 GitHub 运行器用户名作特殊处理。** 运行器身份和临时路径属于部署细节，可以独立于产品发生变化。

## 后果

- 普通 Windows 路径别名不再阻止安装器验证和清理。
- junction 祖先和 junction 后代仍然以失败关闭方式处理。
- 安全判断基于文件系统条目类型和所有权证据，而不是路径拼写。
