# Agent Note: 桌面端跨主机发布检查

Status: implemented

[English](2026-10-02-desktop-cross-host-release-checks.md) | 中文

## 问题

桌面端发布测试覆盖 Windows 安装器行为，而仓库级覆盖率检查在 Linux 和 Windows 上运行。依赖主机的路径解析、gzip 头和子进程可用性会使相同源码在一个主机上通过、在另一个主机上失败。单个主机上的窄范围检查通过，不足以证明安装包符合发布条件。

## 决策

生成的安装器 PowerShell include 统一 gzip 的 OS 头字节，使仓库提交的内容在不同构建主机上可复现。桌面端资源检查在 `lstat` 前以词法方式去掉目录 URL 的尾部分隔符，保留 POSIX 主机上的符号链接检查。Authenticode 模块路径与可执行文件路径始终按 Windows 路径规则组合，不依赖测试主机。启动 Windows PowerShell 子进程的测试只在 Windows 上运行；可移植的配置和生成内容断言仍留在 Linux 覆盖率任务中。Windows 信任检查与安装器探针使用有上限的超时，覆盖托管 runner 的冷启动耗时。

Windows 卸载清理先通过等价的普通盘符根目录校验扩展长度路径的根，再逐层检查带命名空间前缀的后续目录；它仍校验传入的软件包根目录及每个路径分量，不跟随链接目录。Task worktree fixture（测试前置数据）比较规范化路径，因为 Windows 临时目录可能以短文件名形式返回。不同包的不变式、UI 回退 hook、打包入口和涉及安全的目录遍历，即使少量样板代码相同也保持独立；局部重复代码排除不会改变仓库级检测器的阈值。

## 曾考虑的替代方案

**在 Linux 上跳过整个安装器测试文件。** 这会失去安装器配置与生成命令的可移植断言，因此只有依赖子进程的用例限于 Windows。

**在元数据检查前通过 `realpath` 解析资源根目录或回退根目录。** 这会在检查代码拒绝链接目录前就跟随它。词法规范化与逐层检查保留了不跟随链接的规则。

**提高全局测试或重复代码阈值。** 这会掩盖无关回归。实现只调整受影响的超时，并在局部标注刻意相同的样板代码。

## 后果

Linux 与 Windows 校验相同的可移植桌面端发布配置，托管 Windows 仍负责真实的 PowerShell 与安装器生命周期行为。生成的 PowerShell 定义不再依赖压缩器写入的主机 OS 字节。仓库检查全绿仍只是发布的必要条件而非充分条件：辅助安装、修复、升级、卸载、签名和用户机器验收仍各自需要证据。

## 验证

桌面端构建资源、生成的安装器、校验和、卸载清理与 Task worktree 测试覆盖与主机有关的场景。`pwsh-tool-turn` 和翻译提示词的无密钥快照固定了此分支影响的模型可见文本。`pnpm run duplication`、`pnpm run doc-sync` 与 Windows 安装器工作流保留各自独立的检查。
