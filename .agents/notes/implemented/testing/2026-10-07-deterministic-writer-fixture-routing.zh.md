# Agent Note: 确定性的写入者测试路由

Status: implemented

[English](2026-10-07-deterministic-writer-fixture-routing.md) | 中文

## 问题

无密钥隔离写入者模型通过搜索完整组装会话来选择脚本响应。运行时上下文包含临时执行路径。因此，以 `dsh-isolated-writer-a` 开头的随机目录会让 writer-b 选择 writer-a 的脚本，即使执行目录仍然独立。CI 报告独立文件内容错误，但两个轮次都成功结束。

## 决策

写入者 fixture（测试前置数据）适配器从用户消息内容中选择最近一条完全匹配的已知任务文本，不匹配路径、工具结果或其他上下文中的子字符串。缺失任务输入时明确失败。续行选择最近的任务指令，同时保留先前历史。集成 fixture 使用同一规则选择根级和子级脚本。

隔离写入者快照使用普通临时前缀以及包含 `writer-a` 的前缀各运行一次。两者均检查确切文件内容，并将未改变的文本记录与同一预期输出比较。包含冲突名称的前缀在路由修正前复现失败；不通过输出规范化隐藏差异。

## 曾考虑的替代方案

**重试失败的 CI 作业。** 否决，因为随机目录名会掩盖路由缺陷，而不是消除它。

**禁用运行时上下文或修改临时前缀。** 否决，因为真实组装上下文是场景的一部分，其他无关值也可能包含相同子字符串。

## 影响

fixture 保留真实 Loader、agent loop（智能体循环）、文件系统、worktree、持久化和续行行为，只替换模型响应。这改变测试路由，不改变产品权限或子级隔离。[准备](../feature/2026-10-06-isolated-subagent-writer-preparation.md)与[续行](../feature/2026-10-07-isolated-writer-continuation.md)决策继续保留，因为其执行所有权和恢复规则独立于 fixture 选择。本地源码与构建模式快照验证修正；真实模型验收仍然独立。
