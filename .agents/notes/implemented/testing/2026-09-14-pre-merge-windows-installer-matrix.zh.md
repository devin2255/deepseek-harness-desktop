# Agent Note：合并前 Windows 安装器完整矩阵

Status: implemented

[English](2026-09-14-pre-merge-windows-installer-matrix.md) | 中文

## 问题

拉取请求过去只测试一次静默默认目录安装，并关闭所有可选系统集成。完整生命周期矩阵要等推送到 `master` 或发布标签后才运行，因此自定义目录、启用快捷方式、登录启动、修复安装、升级、两种卸载数据选择和危险重定向拒绝都可能在合并后才暴露失败。已经存在生产安装的开发电脑也不能安全替代干净 runner。

## 决策

专用托管 Windows 工作流会在拉取请求、`master` 和 `dsh-v*` 推送上都运行完整安装器端到端测试。该套件继续独立于通用 CI 结论，因为它会修改当前用户的 Windows 安装状态，并且即使后续生命周期断言失败，也要保留已通过校验的发布产物。

## 验证

工作流契约测试要求在工作区构建、安装器打包和最终包校验之后执行一个无条件矩阵步骤。原生 PowerShell 参数覆盖证明矩阵命令原样到达 Vitest。托管套件负责清洁安装、自定义安装、全部系统集成选项、启动、修复、运行中进程升级、保留或删除数据的卸载行为、重定向安全和夹具清理。

## 考虑过的替代方案

**保留单一路径拉取请求冒烟并依赖合并后验证。** 这会让合并成为多数公开安装器要求首次暴露失败的事件。

**在开发者工作站运行完整矩阵。** 现有产品状态可能与固定应用身份冲突；为了测试而删除这些状态并不安全。

**保留冒烟作业并另加完整矩阵作业。** 矩阵第一项已经执行同一个清洁安装冒烟，再构建和安装一次只会重复耗时，不会增加证据。

## 后果

- 每个拉取请求都在合并前承担完整 Windows 生命周期测试成本。
- 安装器要求会在可丢弃的干净用户配置中验证，不会触碰开发者已安装的应用。
- 即使生命周期矩阵失败，通过包校验的产物仍可下载诊断。
