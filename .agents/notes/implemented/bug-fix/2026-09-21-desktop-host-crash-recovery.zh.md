# Agent Note: 桌面 Host 崩溃恢复

Status: implemented

[English](2026-09-21-desktop-host-crash-recovery.md) | 中文

## 问题

Electron Main 已监管 Harness 启动和有意关闭，但没有保留 utility process 在就绪后退出的可观察结果。死亡 Host 可能让已授权 Renderer 与原生后台展示继续依附于不可用的权限；自动重启则可能掩盖中断轮次，或重复执行结果尚未确认的工具动作。

## 决策

作为[可重试桌面启动决策](../feature/2026-08-24-retryable-desktop-startup-and-uninstall-cleanup.md)的扩展，每个就绪 Harness 句柄都会公开一个不可变且不会 reject 的退出结果。Electron Main 立即观察该结果，区分有意清理与意外退出，并为所属启动尝试串行执行一次恢复操作。

意外退出会撤销已授权 Task 窗口，dispose 其关闭订阅与原生后台驻留，只记录尝试 id 和原生退出码，并在本地启动窗口中显示 `service-exited` 故障状态。恢复还覆盖 Task 窗口仍在加载、启动交接正在进行、窗口已原生关闭，以及退出操作抢先于延迟恢复窗口创建的情况。失败尝试中迟到的窗口会先被销毁，绝不会取得所有权。

重启始终是显式用户操作。重试会等待进程与后台资源清理，但不会等待失败尝试中无限延迟的窗口创建。它会取代该尝试，并用新的能力凭证启动一个全新 Harness。旧尝试迟到的退出或窗口完成都不能影响替代实例。

[语义 Session 检查点决策](2026-07-21-semantic-session-checkpoints.md)仍是中断工作的权威机制。冷态修复会用合成的风险分类结果关闭未配对工具调用，并以 `interrupted` 结束轮次。Task 投影把该持久标记显示为由确切 Session 所属、不可直接操作的运行故障；它不会重建进程内的问题注意事项，也不会重放工具调用。

## 曾考虑的替代方案

**自动重启 Harness。** 这会缩短可见中断时间，却可能掩盖故障，并让恢复后的工作流看似一直拥有连续权限。显式重试让用户掌握控制权，并确保任何新模型或工具工作开始前都能看到中断。

**重启期间保留现有 Renderer。** 其隔离 session 带有死亡进程的启动能力凭证与 origin 授权。复用该 Renderer 会保留陈旧权限，并混淆不同进程的所有权，因此恢复流程会销毁它，只在新进程就绪后创建重新授权的 Renderer。

**持久化待回答问题 promise 并恢复同一个工具调用。** promise 与 abort signal 都属于进程内状态，而 Session 日志已经为未配对调用提供通用崩溃修复规则。第二个持久问题存储会与 Session 回放竞争，并可能重复副作用；恢复流程因此改为投影被中断轮次。

## 后果

前台或托盘拥有的 Host 故障后，用户会看到稳定的本地恢复界面；显式点击重试前不会启动任何 Host。每个替代实例获得新的启动能力凭证，持久 Task、worktree 分配、交付回执和已完成事件则通过普通 Session 持久化保留。

聚焦的监管器、启动状态、窗口与生命周期测试固定了进程所有权和竞态行为。真实 Electron 验收会在前台与托盘拥有状态下终止 utility process，验证不会自动重启，重试后获得新授权，证明既有 Task 仍然存在，检查被中断工具调用变为一个持久故障且不会再次向提供方派发，并确认死亡 Host 的托盘与通知状态已释放。

恢复属于本地应用行为，不是操作系统重启服务。断电或计算机重启会在下次正常启动时修复。签名、自动更新和平台启动集成仍是独立发布能力。
