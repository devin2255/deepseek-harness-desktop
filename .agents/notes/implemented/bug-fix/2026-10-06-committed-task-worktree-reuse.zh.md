# Agent Note: 已提交 Task worktree 的复用

Status: implemented

[English](2026-10-06-committed-task-worktree-reuse.md) | 中文

## 问题

worktree 分配保留 Task 创建时的基准，以供审查与交付。如果检查将这一不可变基准等同于当前 HEAD，就会在首次提交后拒绝有效 Task。隔离 Session 的幂等创建请求随后会报告偏离，即使 Git 仍注册同一个托管检出与分支。

## 决策

本地 Task worktree Provider 要求注册的规范路径与分支完全一致。当注册 HEAD 等于记录基准，或 Git 确认该基准是其祖先时，worktree 可用。游离检出、不可用的提交对象或无关历史仍被判为偏离。检查不会修复引用、修改文件或改写分配。

这扩展了[应用托管 Task worktree](../feature/2026-09-09-application-owned-task-worktrees.md)中的复用规则，不替换其隔离、所有权、预检或失败保留决策。[审查与交付](../feature/2026-09-13-task-review-delivery.md)能力继续针对确切的已审查内容授权变更，并记录独立操作回执。

## 考虑过的替代方案

**在每次提交后替换分配基准。** 不予采纳，因为审查与源目录应用需要原始创建基准，而后续提交不是新的 worktree 分配。

**只要求路径与分支匹配。** 不予采纳，因为分支可以保留名称却指向无关历史。Git 祖先关系保留了记录基准这一必需关系。

**只接受审查服务记录的提交。** 不予采纳，因为 Agent 或用户可以在 Task 检出中合法提交。检查验证仓库身份与祖先关系；审查授权仍是独立义务。

## 后果

有效的已提交 Task 可以复用，无需新目录、分配事件或基准替换。仍保留创建基准的历史重写被允许；这不保证保留每个后续提交。缺失或无关历史仍不能复用。子写入 Agent worktree 与显式 Integration 节点仍是独立且尚未完成的产品工作。

## 验证

真实 Git 测试区分后代提交、游离检出与根历史重写，同时检查源分支和文件不变。无密钥真实 Loader 文本记录固定同一组检查结果。Electron 验收在真实审查提交后重试隔离 Session 创建，并在源目录应用前验证原始分配、Task 序号与提交回执未变。
