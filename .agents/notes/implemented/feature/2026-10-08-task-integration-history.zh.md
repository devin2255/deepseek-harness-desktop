# Agent Note: Task 集成历史与冲突注意事项

Status: implemented

[English](2026-10-08-task-integration-history.md) | 中文

## 问题

[写入者批量集成](2026-10-07-batch-writer-integration.md) 在普通工具日志中保留准确结果，但检查 Task 的操作人员需要区分发布、预检冲突、工具失败和未确认尝试。根级不活跃不能证明发布成功。无关批次成功不能掩盖未解决的贡献者，冷态检查也不能激活 Agent（智能体）或重复 Git 变更。

## 决策

Session Task Provider 从根级 `integrate_agents` 调用重建可选的有序集成节点。原生调用按调用 id、轮次和步骤配对；Code Mode 子分发按子调用、父调用、根调用和序列化参数配对。节点 id 由根与调用事件序号派生。不增加 Session 事件或 Task 数据库来重复已有工具结果。

只有完整 JSON 回执匹配已记录的根分配、请求 revision、有序写入者提交与 revision，以及直接子级归属时，才确认已集成或冲突结果。畸形、spill、不匹配或重复结果保持未确认。工具错误保留其诊断。只有根拥有当前实时活动、且已记录的执行区间仍开放时，待完成尝试才显示运行中；丢失所有权或区间关闭绝不代表成功。

经过验证的预检冲突产生根级合并注意事项，其历史结果保持不变。后续成功批次覆盖所选写入者标识，允许修订后的提交和分开的批次；只有完整覆盖才清除注意事项，并把最后完成覆盖的节点记录为 `resolvedBy`。部分或无关成功不会解决它。这记录的是后续集成，不是 Git 当前内容，也不证明冲突已被自动修复。

Task 协议校验与两套 SDK 保留全部五种结果、根归属、有序调用标识、贡献者选择和完整后续覆盖。Provider 实际执行的不变量检查会校验已发布快照中的这些关系。审查页独立于文件列表空状态展示历史，提供只读贡献者选择，并区分根集成与源交付。未解决的冲突禁用 Commit 和 Apply，但允许“要求修改”。冲突注意事项打开根任务审查页；打开页面不会清除冲突。

## 考虑过的替代方案

**增加独立集成日志或展示事件。** 不予采纳，因为既有原生与 Code Mode 日志已经拥有尝试和结果。第二份持久记录可能在失败或冷态回放后发生分歧。

**把空闲状态、没有错误或截断文本当作成功。** 不予采纳，因为进程丢失后发布结果可能不确定。未确认结果要求在重试前检查当前 Git。

**下一次成功后清除所有冲突。** 不予采纳，因为该成功可能涉及无关写入者，或仅覆盖失败批次的一部分。写入者标识覆盖允许修正后的提交，又不会掩盖未完成的参与者。

## 后果

集成结果与冲突注意事项在完整 Host 重启后仍然保留，无需激活 Agent 或执行 Git 变更。准备、续行、[只读子级审查](2026-10-07-isolated-writer-result-review.md)、批量发布和[根交付](2026-09-13-task-review-delivery.md) 记录保持活跃，因为它们仍有独立的所有权和失败原理。更广的[桌面提案](../../proposed/feature/2026-08-14-desktop-agent-mission-control.md) 尚未完成：默认写入者、人工子级提交和集成控件、冲突解决操作、执行租约、孤立目录恢复及完整桌面写入者验收，都不是历史投影所提供的能力。

## 验证

投影测试固定原生与 Code Mode 关联、畸形和不确定结果、生命周期关闭、部分覆盖、无关成功及修订提交。共享协议 fixture（测试前置数据）使用相同有效结果与无效关系检查 Host 校验和两套 SDK。组件与组合 Web 检查覆盖可见历史和根交付；真实 Loader 场景通过四个 Git 写入者执行冲突与成功批次，随后释放整个 Host，并验证冷态节点相同、冲突注意事项保留且 Agent 未激活。其有界进程截止时间包含两次 Host 启动。这些检查不能证明真实模型执行、人工集成控件或签名发布验收。

Electron 验收通过普通的模型可见工具提交已停止的写入者，并集成其结果。真实审查工作区显示集成回执、刷新根任务 Diff，并打开只读参与者检查。Git 断言验证根任务包含该结果，而源 checkout 保持不变，桌面生命周期也达到完全停稳。这是工具驱动的集成验收，不是人工提交或集成控件验收。
