# Agent Note: 隔离写入者批量集成

Status: implemented

[English](2026-10-07-batch-writer-integration.md) | 中文

## 问题

[隔离写入者](2026-10-06-isolated-subagent-writer-preparation.md) 与[续行](2026-10-07-isolated-writer-continuation.md) 保留独立更改，但根级需要准确且可审查的组合结果。依次应用子级，会在后续子级冲突时暴露部分批次。集成到托管根目录必须与向用户源检出交付相互独立。

## 决策

`TaskReviewService.integrate` 接受确切根审查和包含子分配、审查版本与提交的有序批次。本地 Provider 拒绝空、重复、外来、超限、不完整、脏、陈旧或已集成的选择。每个子级 HEAD 必须等于所选提交，其基线必须仍在根历史中。`maxIntegrationInputs` 限制批次，默认值为 16。

Git `merge-tree --write-tree` 不改变 index、分支或工作树，计算合并。`commit-tree` 准备不可达的双父提交，保留贡献者祖先关系。冲突返回确切批次与冲突子级路径，不发布较早的候选结果。全部合并成功后，Provider 重新验证每项审查和工作树干净状态，再在根上发布一次 `merge --ff-only --no-autostash`。子级分支与原始检出保持不变；准备对象可能保持不可达，等待普通 Git 垃圾回收。

最终重新验证完成前均遵守调用方取消。最终发布与验证保留命令截止时间，但不接受调用方取消。Git 失败或最终 HEAD 不一致返回错误，不是回执；不会通过破坏性 reset 掩盖不确定结果。外部 Git 写入者和钩子不受锁定。这不是文件系统事务或执行租约。

显式启用的 `dsh-tool-subagent-control/integrate` Consumer 注册审查、子级提交与集成工具。它要求在可用托管 worktree 中的确切已注册根 Agent，以及与不可变直接父级元数据、Workspace、源目录和 cwd 相符的已记录子分配。活跃或驻留子级会被拒绝；冷检查不会激活它们。变更在执行器中强制检查根级写入权限。经 schema 验证的 JSON 结果使用通用卡片与普通持久化工具结果，不创建第二个 Task 数据库或人工批准记录。

即使 HEAD 不同于原始分配基线，写入者创建仍接受干净且已提交的根。worktree Provider 负责要求干净及捕获 HEAD 的检查；相对原始基线的审查更改不代表未提交工作。后续批次使用已集成 HEAD。

## 考虑过的替代方案

**立即应用每个子级。** 不予采纳，因为后续冲突会留下已发布的早期结果。在改变根之前准备完整候选历史。

**合并到原始检出。** 不予采纳，因为集成先于根级人工审查。[根交付决策](2026-09-13-task-review-delivery.md) 保留 Commit、暂存 Apply 与可恢复 Discard 的所有权。

**自动解决冲突或在失败后 reset。** 不予采纳，因为两者都可能覆盖独立工作或掩盖不确定结果。错误与冲突会保留贡献者分支供检查。

## 后果

显式组合的 agent（智能体）可以审查、提交和集成已停止的隔离写入者，并启动下一批。执行与根交付记录保持活跃，因为其所有权和恢复原理仍适用；本记录只拥有批量发布决策。桌面默认值仍为只读。显式 Integration 节点、持久冲突关注项与解决界面、跨进程租约、孤立目录恢复，以及完整桌面验收仍是未完成的控制中心要求。

## 验证

真实 Git 测试覆盖完整发布、分支保留、源不变、后续冲突不发布、陈旧版本、脏工作树和重复集成。执行器测试覆盖根身份、写入拒绝、活跃与恢复子级、冷所有权、Diff 和插件 dispose（资源释放）。故障测试覆盖进程输出验证、祖先关系、身份、取消顺序和最终 HEAD 检查。真实 Loader 组合仅替换模型响应，通过文件系统工具和根 agent loop（智能体循环）执行四次审查、四次提交、冲突与成功批次，以及后续写入者批次。无密钥证据不能证明真实模型或桌面集成界面验收。
