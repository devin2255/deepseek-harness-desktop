# Agent Note: 桌面端应用内目录选择

Status: implemented

[English](2026-09-26-desktop-in-app-directory-selection.md) | 中文

## Problem

如果 Windows 原生文件夹对话框工作进程在返回路径前退出，桌面用户便无法添加工作区。反复重试同一工作进程也不能输入已知的项目目录，尽管创建工作区本身接受现有的 Host 路径。

## Decision

桌面 profile 禁用 Web 组合包中的自适应目录选择配置项，并组合浏览后端及其配套客户端交互。应用内对话框列出 Host 目录，并允许通过可编辑的面包屑输入完整路径。工作区所有者仍通过 `workspace.create` 接收所选路径；Host 对其验证并规范化。Web profile 保留原生与应用内浏览之间的自适应选择，部署方也可以显式组合原生实现。

## Alternatives considered

**保留原生选择器作为桌面默认选项，并提供重试对话框。** 工作进程若在操作系统选择器显示前失败，用户无法输入已知路径；重复执行也无法完成任务。

**在工作区错误对话框中另加路径输入框。** 这会让组合式选择流程之外出现另一个目录选择所有者，并重复其路径编辑行为。

## Consequences

桌面端无需原生对话框工作进程即可选择目录，并支持粘贴 Windows 盘符路径；默认不再使用操作系统的文件夹选择器。应用内浏览器仍保留现有的 Host 文件系统访问范围和 Windows 盘符根目录无法枚举的限制。桌面组合测试固定所选的后端与客户端配对；真实 Electron 验收测试通过渲染出的对话框输入路径，并观察工作区注册结果。
