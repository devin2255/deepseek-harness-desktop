# Agent Note: 可重试的桌面启动与认证卸载清理

Status: implemented

[English](2026-08-24-retryable-desktop-startup-and-uninstall-cleanup.md) | 中文

## Problem

桌面进程只能启动一次 Harness 子进程，并在启动失败时直接退出，因而没有本地恢复路径。按用户安装的卸载程序还需要一种可选方式来删除可变产品数据，但不能把应用程序可执行文件变成通用文件系统删除命令，也不能沿 Windows 链接进入产品目录之外的数据。

## Decision

启动时限同时覆盖首次读取模块和经过认证的就绪检查。在测量的 Windows 主机上，全新运行时副本加载约需 23 秒，其中同步文件读取约占 21 秒；已读取过的文件则约需两秒。监管进程为每次尝试提供 60 秒，恢复窗口在此期间保持响应；这能容忍冷文件读取，但不代表读取提速。超时诊断保留现有的有界、脱敏 stderr 尾部。减少首次启动 I/O 需要单独验证打包方案，不能通过禁用宿主安全检查实现，也不能把已预热的开发目录当作全新安装。

安装器关闭调用在验证参数后发送精确的 `{ type: 'deepseek-harness:installer-close' }` 单实例通知；普通或畸形通知不能请求关闭。Windows 打包 E2E 启动进程和关闭辅助进程都先验证命令行、环境与 fixture（测试前置数据）标记中的所有权一致，再选择相同的隔离 appData 与 home 目录并获取 Electron 锁。任一 Electron 路径改变之前，两条目录链都必须是普通目录且解析到 fixture 内。重定向 Electron 主目录把 Harness 工作目录和 CLI dotenv 读取限制在 fixture 内，原生 Windows 配置目录环境变量保持不变。只有经过认证的测试参数会在关闭意图分类之前移除。打包程序探测采用 Electron 的默认配置目录选择，要求通过认证的主界面就绪，并通过真实关闭辅助进程验证退出。

Electron 在 `app.whenReady()` 完成之后、启动 Harness 之前创建本地启动窗口。Main 拥有单调递增的尝试记录，每条记录包含一个 `AbortController`、一个最终 Harness 句柄和一个完成 Promise。Supervisor 在运行时文件验证、规范端点发现和认证探针成功各自真正提交时报告里程碑；Main 只把这些回调投影为启动状态，并忽略过期尝试的回调。Retry 只在失败状态接受，它把该尝试标记为过期、中止它、等待其子进程清理，然后只启动一个替代尝试。原生恢复窗口销毁会提交 handoff，在此之前启动窗口一直是单实例事件的当前聚焦目标，提交后 Main 才把已就绪的桌面窗口安装为当前目标。销毁前错误会拒绝 handoff；销毁后的 IPC 清理或报告错误只作为 callback 失败上报，不撤销主窗口所有权，也不停止 Harness。

启动状态和固定生命周期事实追加到产品拥有的桌面日志。恢复渲染器只能请求三个由 Main 拥有的操作：串行重试、`shell.openPath(DesktopLog.currentPath())` 和有时限的应用退出。原始启动诊断绝不进入渲染器状态。Harness supervisor 保留自己的子进程关闭期限，同时 Main 为完整退出等待设置显式期限，使 Electron 能在子进程违反取消约定后终止。

卸载清理在正常运行时解析、单实例锁、Harness 启动或窗口创建之前选定。它只接受一个 `--uninstall-delete-user-data=<token>` 参数，并要求 `DSH_UNINSTALL_CLEANUP_TOKEN` 中存在相同的 256 位无填充 base64url token；格式验证先于恒定时间比较，失败信息绝不回显任一值。安装程序是两个通道唯一的预期生产者，环境通道只由该清理子进程继承。

清理根目录始终解析为显式绝对 `%APPDATA%` 下固定的 `DeepSeek Harness` 子目录。清理拒绝文件系统根目录、缺失或不安全的 APPDATA 值、非目录祖先、任何现存祖先或产品根目录上的符号链接或 junction，以及产品根目录下任意位置的链接或特殊文件。突变前，它以排他创建方式写入同卷私有归档，以 64 KiB 分块流式记录普通文件字节，为每个文件记录 SHA-256 摘要、可移植 mode 与修改时间元数据，fsync 归档，将归档恢复到私有验证目录，并通过提交后将使用的同一组突变操作删除验证树。解析器会先检查固定版本头部、声明与配置的条目数、固定元数据、每条路径 64 KiB 与累计 16 MiB 的 UTF-8 路径元数据上限、安全整数转换，并在任何分配或读取之前，以普通归档文件实际剩余字节校验每次读取；每个已打开归档句柄都会关闭，操作与关闭同时失败时会保留两个错误。没有配置内容字节上限；实际归档大小是每个文件和整个流的硬上界，显式的 100,000 条目上限则约束元数据与遍历工作，并在突变前失败。身份复查后，同卷重命名把规范目录移至事务墓碑。墓碑清除或最终归档取消链接失败时，清理会恢复内容与目录结构，在发布前应用并验证 mode 与修改时间，原子地重新发布规范目录，然后报告失败。创建时间不可移植，因而不会保留。清理会在仍可回滚时确认自有归档是唯一保留产物；归档取消链接是最后一个可能失败的提交操作，成功后不再执行 I/O。随机事务 id 同时写入归档名称和头部。后续经过授权的清理会在突变前枚举每个保留的归档、墓碑、验证和恢复前缀；畸形名称、意外文件系统类型、孤立产物、重复产物和冲突 id 都会被拒绝且保持不变。只有一个头部 id 和每个校验和都验证通过的普通归档，才能授权恢复或删除同 id 的关联普通目录。回滚和中断恢复对每个事务使用同一个确定性恢复名称。中断恢复先在不物化第二棵目录树的情况下认证归档，再安全清除或重建这一个 workspace；再次中断时，至多保留该目录和归档，供下一次授权调用重试。无效仿冒产物保持不变并产生非零结果。目录删除会持有每个目录的打开句柄，并在枚举后、子项突变前和最终删除前复核所有祖先的普通目录类型与 device/inode 身份。任何调用方都不能提供删除根目录，也不能通过依赖注入绕过 token 和路径验证。

Windows 分发物是单个按用户安装的 x64 NSIS 辅助安装程序。它无需提权，默认安装到 `%LOCALAPPDATA%\Programs\DeepSeek Harness`，允许选择目录，并分别拥有桌面快捷方式、开始菜单快捷方式与带安全引号的 HKCU 登录启动选项。每次安装与 repair 都先采用 ON、ON、OFF 默认值，再恢复稳定产品注册表键中每个有效选择，不依赖更新命令行标志。安装程序会在替换可能改写该键之前保留旧安装目录和可执行文件路径；移动安装目录后，只有稳定快捷方式或登录启动值的精确目标是旧或新可执行文件时才会删除它们，随后持久化新位置。固定 PowerShell 5.1 命令生成为 UTF-16LE `EncodedCommand` 值，并与其源脚本逐字节核对，因此系统脚本文件策略无法阻止版本比较、精确路径进程查询或快捷方式所有权检查。动态版本与路径只通过临时环境值传递。快捷方式检查器只有在目标精确等于旧或新可执行文件时才返回零，并为不存在、外部目标和无效快捷方式分别返回非零状态；NSIS 忽略其输出，因为 Windows PowerShell 即使在 `-NonInteractive` 下也可能附加序列化进度记录。SemVer 2.0 解析要求输入绝对结束；无效存储版本、比较失败和尾随字符都会停止替换，已安装版本更新则阻止降级。应用通过子进程辅助程序持有显式稳定的按用户 Windows mutex，但替换操作始终查询精确的已安装可执行文件路径，只把 mutex 当作附加信号。精确路径上的存活进程通过非阻塞辅助进程启动与固定时限轮询接收关闭意图；查询失败或进程仍存活时只会产生 Retry 或 Cancel，绝不强制终止，用户选择的路径也绝不插入 PowerShell 源码。桌面端在选择卸载清理之后、组合任何正常运行时之前，只接受唯一且精确的 `--installer-request-close` 参数。请求进程要么通知已有单实例后退出，要么释放新取得的锁后退出；任何匹配前缀的畸形参数都会失败关闭。卸载数据删除是默认未选中的组件，显示精确 `%APPDATA%\DeepSeek Harness` 路径，并要求再次确认。卸载程序使用 Windows 加密随机源创建清理 token，在每次启动尝试后清除临时环境通道，并把 `ExecWait` 启动错误与非零清理退出码都视为失败。

打包流程先创建 `win-unpacked`，移除已知非目标平台原生负载和会泄露源代码位置的 Rolldown region 生成注释，再验证通过 `--prepackaged` 传给 NSIS 的精确目录。验证要求产品具名的 x64 原生 addon，把每个 `.node` 与 `.exe` 解析为 COFF、可选头、数据目录、节表和节数据范围均有效且有界的 PE32+，解析完整生产依赖与必需对等依赖图，拒绝指向包外的链接，并扫描有大小上限的已发布配置、JavaScript、HTML、CSS 与 source map 文本中的宿主路径。排序后的 NSIS 前后目录树记录包含每个目录、链接目标和普通文件 SHA-256，因此相同文件计数不能掩盖突变。发布元数据具有精确字段集合，并且必须匹配安装程序文件名、当前版本、字节数、SHA-256 与重新读取的 Authenticode 结果。Authenticode 检查通过允许列表子进程环境、超时和输出上限运行绝对路径的 Windows 自带 PowerShell，绝不继承打包进程环境。签名接受完整的 `WIN_CSC_LINK` / `WIN_CSC_KEY_PASSWORD` 对或完整的 `CSC_LINK` / `CSC_KEY_PASSWORD` 对，拒绝任一不完整变量对，并在两组都完整时优先使用 Windows 专用变量对。

NSIS 环境变量 API 调用会保存并恢复临时寄存器。Windows API 返回值不得覆盖命令退出码、快捷方式所有权结果、清理启动标记或关闭轮询计数器。原生回归测试会编译并执行安装器指令片段，因为只测试 PowerShell 无法观察 NSIS 寄存器突变。安装器生命周期测试在启动前清空本次 trace，并同时要求精确完成事件和安装产物；旧安装留下的文件不能证明 repair 已完成。

安装器测试的集成名称包含唯一的 fixture 目录名；共享固定安装叶目录名会让原本隔离的 fixture 共享桌面快捷方式、开始菜单条目和登录启动注册。仅验证文件系统的测试采用目录清理，不能调用卸载器或改变 Windows 集成。完整生命周期清理还会验证注册表所有权；真实安装器测试仍须串行，因为 Windows 产品注册使用稳定的按用户标识。

安装器 CI 在全新的托管 Windows runner 中执行安装变更，不使用共享的原生故障切换账户。共享 Windows 汇总在工作区构建和桌面验收消费者都结束后，以观察方式执行打包与验证，避免打包改写运行中 Electron 测试使用的文件。独立产物工作流不持有签名凭据，只保留通过包验证的发布文件，即使上传了诊断产物，验收失败结果仍然可见。[桌面说明](../../../../apps/desktop/README.md#windows-installer-development) 区分无凭据启动、注册版本替换与断网机器、旧发布产物验收。

安装程序的文件删除钩子对安装目录树和更新暂存目录树使用扩展长度的盘符路径或 UNC 路径。嵌套运行时依赖可能只有在移入更长的临时目录后才超过传统的 260 字符限制，导致普通同版本修复中止。[生成器](../../../../scripts/desktop/generate-installer-file-operations.ts) 适配固定版本 electron-builder 的移动和恢复函数，不改变其遍历或回滚算法；生成前检查规范化上游模板的摘要，打包时拒绝陈旧的生成输出。原生 NSIS 测试覆盖成功移动、后续移动失败后的恢复以及普通卸载。这些操作只影响已安装的程序文件，不影响单独经过认证的可变数据清理。

## Alternatives considered

**便携 ZIP、一键安装或 MSI。** 便携 ZIP 不提供所需的安装和卸载流程；一键安装隐藏了必需的目录与集成选项。辅助 NSIS 提供这些选项，并使用经过验证、自包含的生产暂存目录树。MSI 增加了本次按用户安装范围之外的企业部署语义。

**由首个实例把第二次启动的原始命令行解释为关闭通知。** 拒绝，因为 Electron 和安装器测试可能附加调用方关闭意图以外的参数。请求进程先验证调用再发送显式通知；接收方不会为了识别转发的元数据而放宽唯一参数规则。

**缩短测试目录，或在替换前直接删除旧程序目录树。** 拒绝，因为缩短 fixture 会掩盖用户较长路径下的故障，而先删除会丢失上游回滚行为。扩展长度路径保留真实的安装生命周期测试和现有恢复算法。

**首次启动错误后退出。** 拒绝，因为运行时和配置错误可以恢复，而终止会移除解释和重试故障的唯一产品自有界面。

**点击 Retry 后立即启动替代子进程。** 拒绝，因为重叠子进程可能争用可变 Harness 状态，并允许旧尝试的延迟完成替换当前 UI 状态。

**从命令行接受清理路径。** 拒绝，因为被利用或意外的调用会把已签名桌面二进制变成任意递归删除工具。

**只用命令行标志或可预测 token 授权清理。** 拒绝，因为普通桌面启动也能提供命令行参数。独立继承的高熵环境值把授权限制在卸载程序创建的子进程。

**直接对产品路径使用递归删除。** 拒绝，因为 Windows junction 处理可能遍历到拥有目录之外，而且树中途失败不能恢复已经删除的条目。后代链接拒绝、已验证恢复归档、规范路径原子重命名和链接感知删除既保护外部目标，也能在已提交删除失败后恢复规范内容。

**使用 Electron Builder 的默认快捷方式与运行进程处理。** 拒绝，因为默认行为不能表示三个独立且持久化的选择，并可能在替换期间强制终止进程。仓库拥有的 NSIS hooks 会保留选择，并要求有时限的优雅关闭。

## Consequences

启动失败会保留可用的原生恢复窗口，重试不会重叠受监管子进程。桌面端增加了生命周期状态和完整清理期限；若期限到期，Electron 会在报告失败后退出，即使有缺陷的子进程可能仍然存在。辅助卸载会删除规范可变数据根目录而不暴露通用删除接口。每个普通非零结果都会保留规范内容、目录结构、修改时间与平台支持的权限 mode；它不承诺相同创建时间或其他文件系统特有元数据。致命恢复诊断会保留已验证私有归档，供后续经过授权的恢复尝试使用。在不存在同用户主动并发命名空间突变时，零结果表示产品数据和自有事务产物都已不存在。大型 session 会占用与普通文件字节量成比例的同卷临时归档空间，而流式处理使内存有界。这些检查防御预置链接与偶发并发重定向。Node 没有 Windows 句柄相对删除原语，因此持续运行且具有同一 Windows 用户权限的进程可以在每次身份检查后替换路径；清理不宣称对该攻击者具备原子安全性，也不为此引入原生 addon。安装程序代码必须生成新的 32 字节值，将其编码为 43 字符无填充 base64url，通过两个清理通道传递，并避免让任何无关进程继承该环境值。

两组受支持证书变量都未配置时，安装程序保持未签名，因此本地构建可能触发 Windows SmartScreen。桌面拥有单实例锁期间，显式 mutex helper 会增加一个隐藏子进程；关闭其 stdin 会在进程退出前释放 mutex。
