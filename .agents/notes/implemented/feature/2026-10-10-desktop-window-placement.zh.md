# Agent Note: Main 拥有桌面窗口位置

Status: implemented

[English](2026-10-10-desktop-window-placement.md) | 中文

## 问题

监督任务时，用户会在 Harness 仍活动的情况下反复关闭并重新打开原生窗口。固定的创建尺寸会丢失用户布局，而直接恢复旧坐标可能使应用落在所有已连接显示器之外。原生窗口位置是设备偏好，不是 Task 或 Session 事实。

## 决策

Electron Main 在产品数据目录中拥有带版本的正常窗口矩形和最大化偏好。[桌面基础](../architecture/2026-08-14-electron-desktop-foundation.md)继续拥有进程与授权；窗口偏好不增加 Renderer API、模型输入或 Session 事件。[Electron 正常窗口边界](https://www.electronjs.org/docs/latest/api/browser-window#wingetnormalbounds)在最大化、最小化和全屏期间保留普通窗口矩形。只有最大化会恢复；临时模式不会隐藏下次打开的窗口。

创建时选择与已保存矩形交集最大的当前可用区域。没有交集时选择主显示器。窗口尺寸和整个边框按设备无关像素限制在该可用区域内，包括负坐标显示器。可用区域小于正常最小尺寸时，原生窗口最小尺寸会降低以适配。每次重建都在 Electron 就绪后读取显示器信息，不沿用上次启动的显示器数据。

在观察或最大化前，Main 应用矩形并读取原生结果。有界反馈校正实际测得的边框与非整数缩放舍入，包括原生最小尺寸，不硬编码 DPI 偏移。仅传入构造参数不足以恢复：125% Windows 缩放下的原生验收观察到创建尺寸增长，以及较小的 setter 差异。无法稳定到请求矩形的原生窗口会被销毁，并通过启动恢复报告，而不是发布持续漂移的偏好。

存储只接受大小有上限、版本与字段完全匹配的普通文件。读取或解析失败会记录诊断，不阻止启动。原生变化立即捕获分离的值，并通过既有原子写入器防抖发布。唯一的串行写入器发布最新捕获的状态，旧写入不能覆盖新写入。窗口关闭释放监听器并开始发布。显式退出会捕获实时窗口位置、移除观察者，并在释放应用 mutex 前等待发布；此清理完成后，晚到的窗口事件不能再排入写入。存储和诊断失败不会逃逸原生回调，也不会终止 Task。

## 考虑过的替代方案

**将窗口位置存入 Session 事件或 Renderer 存储。** 这一偏好属于设备而非某个 Task，已授权窗口重建也会获得新的 Renderer。Main 已拥有原生生命周期，另一条传输或任务事实不会增加有用的权限。

**不检查当前显示器，直接恢复已保存矩形。** 显示器移除、缩放变化和可用区域缩小都可能使标题栏无法触达。创建窗口以当前可用区域为准。

**只在窗口关闭时保存。** 后台运行和异常退出可能绕过普通关闭。合并持续写入可保留最近已发布的偏好，显式退出负责最终发布。同步保存每次移动则会阻塞原生事件分发，并产生不必要的磁盘写入。

## 后果

窗口重建保留用户布局，不启动另一个 Harness。有界偏好格式拒绝不受支持的版本，不维护兼容层。原子替换阻止不完整 JSON 成为已发布文件，但不承诺断电持久性；发布前终止可能丢失最新布局。全屏刻意不作为记忆模式。显示器调整应用于创建窗口时；此存储不会在原生显示器变化期间移动实时窗口。

## 验证

窗口位置与存储测试覆盖显示器缺失、负坐标、小屏幕、无效持久数据、串行写入、监听器清理及失败。无密钥的已构建 Electron 流程固定磁盘发布、单个 Harness 下的同进程重开、冷启动最大化、正常尺寸恢复、屏幕外位置恢复，以及无效偏好的诊断。原生验收属于 Windows 和 macOS 桌面检查；单个主机上的运行不能证明另一平台或签名安装器符合条件。
