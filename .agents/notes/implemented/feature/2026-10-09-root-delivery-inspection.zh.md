# Agent Note: 观察待核实的根任务交付

Status: implemented

[English](2026-10-09-root-delivery-inspection.md) | 中文

## 问题

Git 结果丢失后，交付日志仍保留授权，但缺少回执无法区分操作未执行、已完成或部分变更。仅凭 HEAD 无法识别授权结果。普通状态查询可能因索引缓存或标志而隐藏文件改动。把当前时间记为执行时间会伪造历史事实。

## 决策

Review 服务拥有 `TaskDeliveryIntent` 和请求范围内的交付观察。结果区分 `completed`、`not-completed` 与 `ambiguous`，携带已记录意图、Task 与 Workspace 身份、内容 revision 和观察时间。已完成效果包含当前 Git 事实，不包含执行时间或回执。未完成表示授权效果此刻不存在，不证明 Git 从未发生变化。观察时间不参与 revision。

Commit 将授权父提交与预备树同当前提交比较，并要求索引和文件干净。原 HEAD 与原审查内容表示没有完成 Commit，包括仅暂存的准备。Apply 要求确切的已提交 Task 审查和源 HEAD，在私有索引中模拟完整且有界的 patch，并将目标与实际源索引及文件比较。无关或部分内容保持不确定。Discard 要求记录路径和注册项均不存在，没有迁移后仍使用保留分支的 worktree，且授权分支 HEAD 保留原基准祖先。丢失与恢复信息来自持久预检，而不是更早的 Commit 回执。

核验把实际索引复制到私有目录以取得暂存树，再创建并刷新一个全新的私有索引，检查文件时不继承 stat 缓存、assume-unchanged 或 skip-worktree 标志。清理失败会拒绝返回观察结果。普通读取禁用可选 Git 锁。模拟可能留下不可达对象；用户索引、文件、引用和 Session 事件均保持不变。

核验共享 Provider 的规范化 common-directory 队列，即使 Task 已删除也从经过验证的源根目录发现该队列。两次分类不同会返回不确定状态。此队列不是跨进程锁或文件系统事务。

Host 仅接受根 Session id 与操作 id。它从已附加或冷态持久日志解析所有权和未完成授权，在整个核验期间持有根执行所有权，并在返回前重新检查授权。冷态根仍保持冷态。缺少授权时拒绝核验，包括实时回执等待持久化的情况，此时应使用已有的检查点保存路径。观察不会清除注意事项或授权重复执行 Git。

## 考虑过的替代方案

**构造人工合成的执行回执。** 被否决，因为当前 Git 状态匹配不能证明因果关系或执行时间。观察和后续人工确认是独立事实。

**仅匹配 HEAD 或 patch 是否存在。** 被否决，因为无关提交与部分应用的文件可能类似授权结果。确切父提交、树、索引、文件和所有权仍不可省略。

**信任普通 Git 状态。** 被否决，因为缓存元数据和索引标志可能隐藏文件改动。全新私有索引在检查文件时保留用户索引。

**自动重试或清除未确认交付。** 被否决，因为观察不等于授权，此刻效果不存在也不能证明此前没有副作用。

## 后果

Host 可以报告当前 Git 证据，不必伪造成功交付事件。持久人工结算、SDK 核验方法和 Review 确认控件仍未完成。此能力不解除执行限制、不授予新的变更权限，也不代表签名发布验收已完成。

## 验证

真实 Git 测试区分完整、缺失、部分、外部改动、隐藏文件改动和未完整删除的结果，并比较用户索引字节。进程与文件系统故障覆盖有界读取、无效身份、模拟冲突、并发改动、取消及清理失败。Host 传输测试拒绝客户端提供的事实和不一致效果；执行测试保留所有权、冷态与未确认注意事项。

真实 Loader transcript（文本记录）丢失已完成的 Commit 响应，重启完整 Host，再通过类型化 Host 客户端检查确切授权父提交和树。它验证索引与历史未变、没有执行时间、未激活冷态 agent（智能体），且不确定状态仍保留；随后文件改动会产生不确定结果。这些检查不证明人工结算或桌面确认控件已经完成。
