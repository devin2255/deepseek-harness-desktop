# Agent Note: 桌面只读委派

Status: implemented

[English](2026-10-06-desktop-read-only-delegation.md) | 中文

## 问题

根任务 worktree 会隔离并行桌面任务，但普通进程内子级共享父级的 cwd。因此，继承可写父级会允许多个 agent（智能体）修改同一个任务 checkout。研究与审查子级不需要这种权限。[任务控制提案](../../proposed/feature/2026-08-14-desktop-agent-mission-control.md)要求普通子级只读，并行写入者使用独立 worktree。

## 决策

沙箱策略归属方提供 `delegationMode: inherit | read-only`，默认继承以保留既有组合行为。桌面覆盖层显式选择只读，并保留部署的根模式与回退目录。一次性和可继续创建都会在第一次 await 前捕获 `delegatedModeOf(parent.session)`，并在未发布设置阶段、任何 fork 历史之后，追加相应的 `sandbox/mode` 事件。既有文件系统与子进程消费方强制执行所记录模式；工具可见性过滤或 UI 标签均不授予或拒绝文件权限。

这扩展而非替换了[委派时策略继承](2026-07-25-subagent-policy-inheritance.md)。继承模式只复制父级显式覆盖项。只读委派即使在父级没有覆盖项或拥有完整访问权限时，也会记录自身更窄的子级模式。一次性批准授权与根部署默认值不会被复制。子级既有审批钉定仍为 `never`，因此模型不能通过审批提示为被拒写入升权。

冷态可继续子级重放已记录的创建策略。修改部署设置只影响新委派，不影响已经创建的 Session。该模式使用既有持久事件与当前策略运行时上下文；没有第二份权限记录，也没有新的 Session 格式。

## 考虑过的替代方案

**修改所有 profile 的子级默认值。** 不予采纳，因为通用 CLI（命令行界面）与 Web 组合有意允许继承可写子级。桌面产品通过显式组合拥有更窄的选择。

**对子级隐藏修改工具。** 不予采纳，因为 shell 命令与其他能力调用方仍可写入。操作的沙箱策略必须拒绝该效果，不能依赖工具展示。

**收紧整个任务。** 不予采纳，因为根任务需要实现并集成修改。委派记录子级专用模式，不修改其父级。

## 后果

新的桌面 spawn、fork、嵌套与可继续子级可以检查共享任务文件，但不能通过沙箱强制执行的操作修改它们。父级可写模式与陈旧可写 fork 历史不能放宽它们的创建策略。其他 profile 保留继承默认值。已有持久化子级保留原始策略，因此这不会追溯性撤销在线或冷态 Session 的权限。

子写入者 worktree、显式 Integration 节点与冲突注意事项仍是必须完成的产品工作。此决策不提供并行写入，不能据此将更广泛的任务控制提案标记为完成。进程外提供方保留自身部署策略。

独立配置的[隔离写入准备](2026-10-06-isolated-subagent-writer-preparation.md) 提供子 worktree 中的单次执行，不改变此共享子 agent 默认值。它的显式权限与持久执行记录不会取代此委派决策。

## 验证

策略测试固定两种委派选择、父级不可变性、省略默认值及不支持设置的加载时拒绝。真实文件系统测试拒绝来自未切换、workspace-write 与完整访问父级的写入，并覆盖可写 fork 历史。继续执行测试通过持久化与冷恢复保留已记录策略。桌面组合包测试检查已分发 patch，无密钥 Loader 快照在可写根下固定仅父级继承与部署选择的只读子级，包括从外部验证输出文件不存在。
