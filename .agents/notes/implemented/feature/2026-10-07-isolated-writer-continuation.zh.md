# Agent Note: 隔离写入者续行

Status: implemented

[English](2026-10-07-isolated-writer-continuation.md) | 中文

## 问题

[隔离单次写入者](2026-10-06-isolated-subagent-writer-preparation.md) 能够实现独立更改，但后续指令需要使用同一检出和记录的权限。普通[可续行子 agent](2026-07-28-continuable-subagent-conversations.md) 独立于建立它的提供方，从 Session 重建执行。仅有目录字符串无法证明恢复的写入者仍拥有已注册的 Git worktree。

## 决策

`ContinuableCreateSpec.execution` 提供分离的 cwd、捕获的策略和非展示初始化事件。继续执行管理器在未发布设置阶段持久化这些输入，并添加必需且模型不可见的 `subagent/execution-provider` 记录。初次创建和冷恢复时，记录的提供方必须仍注册 `validateContinuableExecution()`。管理器将其身份与子 agent 自身的描述符比较，并传入实际尚未发布的 header 和事件，而非较早的持久化检查结果。校验、取消及父级关闭检查先于发布和收件箱准入。只有管理器拥有创建、激活、投递和 dispose（资源释放）；提供方不会收到子 agent 句柄。

隔离 spawn 校验器要求直接根 Task 的托管集成分配，匹配的子 id、父级、来源、cwd 和源目录，记录的 workspace-write 或更窄的 read-only 权限，以及审批 `never`。worktree 服务校验实时规范 Git 路径、已注册分支和基线祖先关系。允许子目录存在脏文件。目录缺失、分支 detached 或被替换、权限升高及所有权不可用均会拒绝恢复，不接受后续消息。冷恢复绝不创建另一个 worktree，也不捕获父级的新权限。

工厂的同步发布提交点还要求已校验的提供方仍以同一身份注册。异步校验或后续设置期间移除或替换提供方，会回滚尚未发布的子 agent；已完成的回调不能在其提供方消失后授权发布。

事件声明归公开类型模块所有，使外部消费方获得其 Session 扩展。NodeNext 声明检查在独立项目中编译各包拥有的 `tests/node-next-types.mts` fixture：同时导入全部工作区 API 可能通过无关扩展掩盖声明缺失。标准的规范符号链接解析使 peer 导入使用同一个 Session 类型实例；保留工作区链接路径可能使该实例与其扩展分离。隔离的 subagent fixture 要求执行事件存在，并拒绝缺少提供方字段。

普通共享目录子 agent 没有执行提供方记录，保留与提供方无关的冷恢复。fork seed 不提供执行权限：校验读取子 agent 自身的事件后缀。模型路由与策略捕获一样，在异步准备之前解析。

## 考虑过的替代方案

**信任持久化 cwd。** 不予采纳，因为路径可能消失，或指向 detached 或被替换的检出。记录的所有权必须与实时 Git 身份一致。

**让提供方恢复或持有子 agent 句柄。** 不予采纳，因为这会重复激活所有权、收件箱顺序和子级优先释放机制。校验不修改 Agent 生命周期。

**只校验初步持久化检查。** 不予采纳，因为工厂可能恢复较新的存储版本。校验输入必须是即将发布的 Session。

**要求每个共享目录子 agent 保留其初始提供方。** 不予采纳，因为普通重建不需要外部执行资源。只有显式执行提供方记录才引入该依赖。

## 后果

[写入者批量集成](2026-10-07-batch-writer-integration.md) 负责已停止结果的审查和发布，不接管续行生命周期。[人工子结果检查](2026-10-07-isolated-writer-result-review.md) 仍独立于这些模型工具。

显式隔离可续行写入者跨驻留时段保留检出、transcript（文本记录）和创建权限。卸载其校验器会使后续冷激活不可用，而非静默恢复为共享执行。既有共享子 agent 续行和单次运行所有权保持独立。创建取消或失败时保留已准备的检出作为恢复数据。

准备及通用续行记录保留为活跃记录：其干净基线与单收件箱所有权原理仍适用，本记录拥有执行校验决策。[桌面只读委派](2026-10-06-desktop-read-only-delegation.md) 仍是已分发默认值。显式 Integration 节点、冲突关注项、子结果变更操作界面、孤立目录恢复及桌面写入工具组合仍是未完成的[任务控制中心要求](../../proposed/feature/2026-08-14-desktop-agent-mission-control.md)；这不代表并行协作或桌面 MVP 已完成。

## 验证

真实 Git 与 agent loop（智能体循环）测试在冷恢复前后写入文件，保留唯一分配和执行所有者记录，且保持源与集成检出不变。detached 分支恢复遭拒，不会发布子 agent。持久化数据测试拒绝矛盾元数据及升高或缺失的策略，同时允许降低权限。续行测试固定校验器缺失、提供方移除、校验期间取消和描述符不符时在发布前拒绝。解码器测试拒绝格式错误和重复的持久执行所有者记录。

无密钥真实 Loader 写入 transcript 使用实际文件系统工具验证单次并发、续行写入、权限保留和分支身份拒绝。两种 SDK 子进程测试在子通知中保留同一执行所有者 fixture（测试前置数据），不会将其加入根事件。缺少 API 密钥时真实模型执行仍未验证；不提供跨进程邮箱和租约恢复。
