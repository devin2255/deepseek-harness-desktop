# Agent Note: 持久根任务交付授权

Status: implemented

[English](2026-10-08-root-delivery-journal.md) | 中文

## 问题

[根执行互斥](2026-10-08-root-delivery-execution-exclusion.md)会在人工 Git 交付期间阻止受支持的根执行，但排队输入仍可追加 Session 事件。若完成时与最初的 Session 序列比较，Git 成功后仍可能拒绝有效回执。变更与回执之间发生进程丢失时，也需要持久证据表明交付可能已修改 Git。

## 决策

Host 与 SDK 在授权、Git 和回执结算期间持续持有根维护或离线所有权。本地 Review Provider 在仓库队列内、预检之后、修改用户索引、worktree 或分支之前，等待调用方拥有的授权。调用方记录并持久化 `task/delivery-started`，包含唯一操作 id、确切审查 revision、操作类型与该变更所需输入。预检失败不创建意图；授权失败阻止这些用户仓库变更。

Commit 授权包含已审查 HEAD 和通过私有临时索引准备的确切目标 Git 树。成功与失败都会移除该索引及其锁；准备可能留下不可达对象，但不改变真实索引或发布提交。Provider 在授权前后复查审查版本，将真实暂存结果与授权树比较，并在返回回执前检查结果提交的父提交和树。钩子或过滤器造成不匹配时保持待核实状态，不声称另一棵树曾被授权。此检查不构成跨进程锁。

Task 服务在授权时而非完成时比较 `expectedSeq`。完整 Provider 回执必须与待完成的操作 id、类型及 revision 匹配；应用还需匹配授权提交与源 HEAD。Discard 授权包含 Provider 观察到的当前 worktree HEAD 和实际未提交变更标记；该标记为真时必须明确确认。其回执报告相同损失标记，并提供等于该 HEAD 的恢复提交；仅当 HEAD 等于分配基准时不提供恢复提交。最初的 Commit 回执仍是独立历史事实。其间允许存在无关 Session 事件。Task 元数据更改和重叠授权仍被阻止。缺少前置意图的回执或不完整的预发布意图会被拒绝。

Discard 在授权完成后重新检查当前审查和未提交变更标记。内容、HEAD 或损失事实变化会在删除目录前拒绝操作，同时保留待核实意图。此复查缩小检查点期间的变化风险，但不宣称拥有跨进程文件系统锁。

未完成意图产生稳定且归根任务所有的 `delivery-unconfirmed` 注意事项。授权后的 Provider 或检查点失败不代表 Git 保持不变。冷态回放保留意图，不重复 Git 或激活 agent（智能体）。只要该注意事项存在，全局 `agent/pre-step` 监听器就拒绝根执行；普通 Task 通过 `next()` 委派。审查页显示操作 id，禁用与执行相关的 Task 操作，并允许只读刷新和检查。

实时回执追加会在持久化完成前同步发布。因此，Provider 独立保留交付检查点的所有者，直到 `sessions.flush` 成功。在这段时间及检查点拒绝后，投影保持未确认状态，替换实时代次也不会清除它。新进程从持久化日志派生状态。这个进程内检查点事实记录持久性不确定，而非另一套持久 Task 历史。

只有确切回执追加已返回且原 Session 实例仍附加时，检查点才可重试。`retryableDeliveryCheckpoint` 提供该操作 id；串行重试只 flush 同一个 Session，不追加事件，也不执行 Git。flush 后再次检查归属。Session 被替换或分离会移除重试资格，但不清除待核实状态；归属仍有效时，保存失败仍可重试。审查页和两套 SDK 都提供该操作，不要求可读取的 worktree，因此丢弃已移除目录也不会阻止保存回执。

## 曾考虑的替代方案

**完成时继续与最初序列比较。** 不予采纳，因为非唤醒注入可合法推进日志，而不改变已授权的 Git 操作。按操作关联可保留授权，不把整个区间当成独占事件容器。

**将 Discard 与最初的 Commit 回执匹配。** 不予采纳，因为有效的已提交 Task 可能继续编辑或产生后代提交。目录删除后再比较会拒绝已成功且经过授权的清理，而已删除文件无法重建其损失事实。变更前的 HEAD 和损失事实可针对当前人工审查保留严格关联。

**只记录成功回执。** 不予采纳，因为 Git 变更后崩溃时，没有证据能区分未触及的操作与丢失的结果。

**仅靠审查摘要恢复 Commit。** 不予采纳，因为该摘要描述工作树路径、模式和字节，而非结果 Git 树标识。已提交的重命名与 Git 过滤器可能改变这种表示。持久化确切父提交和准备好的 Git 树，便可直接比较候选提交，无需重建已删除文件或虚构执行时间。

**每次出错都清除意图或自动重试。** 不予采纳，因为取消和输出丢失不能证明 Git 未改变。重复提交、应用或破坏性丢弃不是安全的默认恢复行为。

**在整个 Git 操作期间持有 Task Provider 队列。** 不予采纳，因为仓库变更与根执行各有所有者。Task 队列只串行校验、追加和检查点工作；缓慢的 Git 操作不会预留无关 Task 的元数据。

## 后果

人工交付具有持久授权与关联完成，但 Git 和 Session 持久化不是同一原子事务。缺少确切实时回执的未确认操作需要检查当前 Task 与源 Git 状态。此机制不提供人工采纳或明确的未变更结算；只读刷新不能清除不确定状态。此日志不会锁住外部进程和子级执行，也不代表人工写入者控制、冲突解决或签名发布验收已完成。

执行互斥、[离线预留](2026-10-08-offline-session-reservations.md)、[根审查](../feature/2026-09-13-task-review-delivery.md)、[排队维护](../feature/2026-07-30-queued-manual-compaction.md)、[已提交 worktree 复用](../bug-fix/2026-10-06-committed-task-worktree-reuse.md)和[集成历史](../feature/2026-10-08-task-integration-history.md)记录继续保持活跃。此决策部分加强交付排序与恢复，不替代它们独立的执行、输入顺序、Git 身份和工具结果原理。

## 验证

严格回放测试拒绝格式错误的意图、跳过授权、重叠变更、身份不匹配、错误源 HEAD 和未经确认的数据丢失。Provider 测试在真实 Git 变更前等待或拒绝授权。运行时测试在延迟或失败的实时检查点期间保留注意事项，拒绝根步骤、委派普通步骤，并恢复冷态不确定状态。Host 与 SDK 测试区分预检拒绝和授权后的结果或检查点失败。真实 Loader transcript（文本记录）在冷态和常驻根上执行提交、应用与丢弃，检查其间注入及持久意图；真实提交结果丢失后，完整 Host 重启仍保留未确认状态，不重复提交或发起模型请求。

两套 SDK 预期输出场景都把真实客户端连接到 Loader 组合的 Task 服务和真实 SDK 传输。它们验证意图通知、回执关联、源文件字节与 HEAD、分支保留和 worktree 删除，随后丢失真实 Git 提交响应，验证冷态注意事项、回执缺失和重复操作被拒绝。必需的 Python 运行时任务显式执行其已构建 Node 配套验证；这不属于单一可执行文件或真实模型验收。

Commit 回归测试将授权父提交与树同真实 Git 提交比较，涵盖重命名和二进制文件，并断言授权尚未改变真实索引。私有准备或授权期间发生变化，会在真实暂存前拒绝；暂存树、钩子结果和畸形树场景拒绝返回成功回执，并移除私有索引。Loader 回放在丢失提交结果并完整重启 Host 后保留确切目标；两套 SDK transcript 将通知目标与已完成及结果丢失的 Git 提交对照。

两套 SDK 场景还让真实提交回执检查点失败，保存确切的实时回执，并在完整运行时重启后恢复它，同时 Session 序号与 Git 提交保持不变。实时和冷态下，缺少回执的重试均被拒绝。Provider 测试覆盖提交、应用和丢弃检查点重试、持久化再次失败、id 不匹配及 Session 归属丢失；UI 测试在审查目录不可读时保留保存操作，断连时禁用。

Loader 和两套 SDK 场景在 Commit 与 Apply 后继续修改 worktree，授权新的审查，并在冷态回放前后验证 Discard 的损失事实和保留的当前分支 HEAD。常驻 Loader 与 SDK 场景还独立推进 worktree HEAD，而不改变最初的 Commit 回执。Provider 测试在授权期间文件内容或纯暂存损失事实变化时保留目录；严格回放测试拒绝格式错误的预检事实、未确认损失和不匹配的恢复回执。

HTTP 传输测试把确切的检查点操作 id 传过 Client 和严格路由解析器，保留待核实投影与已保存回执，并保持事件序号不变。操作 id 缺失或格式错误、Session id 为空白及请求包含未知字段时，均在 Task 实现运行前被拒绝。

Chromium 场景通过桌面 Task 覆盖层启动真实 Web 组合包，执行真实提交与丢弃，并让各自的首次回执保存失败。它通过 Host 传输重试，不增加事件或改变 Git 身份；目录移除后重新加载 renderer，再从交付待核实注意事项进入根审查。浏览器快照固定待核实与已确认状态；源文件字节及 HEAD 保持不变。
