# Agent Note: 离线 Session 保留

Status: implemented

[English](2026-10-08-offline-session-reservations.md) | 中文

## 问题

[写入者审查](../feature/2026-10-07-isolated-writer-result-review.md)和[批量集成](../feature/2026-10-07-batch-writer-integration.md)要求写入者停止。在 await 前后检查注册表驻留状态，无法阻止 Agent 在 Git 检查或变更期间恢复。仓库队列为 Provider 变更排序，但不拥有 Agent 发布。

## 决策

`AgentRegistry.withOfflineSessions` 同步获取整个已去重、没有 Agent 的 Session id 集合，并保留到异步操作完成。在线 Agent 或重叠保留拒绝整个获取；无关标识仍可使用。调用方为其操作提供取消。成功和失败均释放全部捕获的 id，不受调用方数组之后的修改影响。

注册表在 `create` 和 `resume` 入口拒绝已保留 id，并在权威 `enter` 处强制检查。因此，更早开始的准备也无法在离线操作拥有 id 时发布 Agent。工厂现有的未发布事务回滚竞争失败的作用域和未通知 Session。自定义工厂同样必须通过 `enter` 发布；保留不能替代其驱动器排序义务。

操作保留继承的发起 Agent，并参与注册表现有的返回 Promise 等待机制。不引入第二个取消控制器、就绪状态、Agent 状态、模型消息或 Session 事件。被保留的冷 Session 保持冷状态。

Host 在归属检查及完整摘要或 Diff 读取期间保留所选写入者，把竞争映射为 `REVIEW_STALE`。显式启用的写入者工具在检查归属前保留全部所选写入者，并将整个批次保留到审查、提交或集成完成。确切根权限、沙箱写入许可、持久化直接子级标识和当前 Git 审查验证仍是独立要求。

## 考虑过的替代方案

**Git 返回后检查驻留状态。** 拒绝，因为检测到新 Agent 时，它可能已经写入文件。事后的错误不能撤销结果不明确的变更。

**仅从 `agent/created` 监听器否决。** 拒绝，因为通知顺序不是发布权威。`enter` 阻止保留期间的任何创建通知或受支持驱动器启动。

**仅为 Git 操作排队。** 拒绝，因为恢复的 Agent 可以通过审查 Provider 以外的文件系统或 shell 工具写入。仓库串行化与离线 Session 保留保护不同的所有者。

**用新生命周期状态暂停所有在线 Agent。** 对离线写入者拒绝，因为它们必须没有驻留句柄。空闲驻留维护已有 `Agent.runMaintenance`；它不能阻止冷 id 被激活。

## 后果

离线操作不会与所选写入者上受支持的进程内 Agent 激活重叠。它不锁定外部进程、Git 钩子、文件或共享目录 Agent。它随操作结束，不为后续调用提供权限。根级人工交付仍需要自身的维护、命令排序和持久化操作记录；本决策没有完成写入者人工控件或跨进程执行租约。

现有写入者审查和集成记录继续保持活跃，因为它们拥有归属、版本授权、批量发布和 UI 语义。新保留部分加强了写入者已停止的保证，但不替代那些决策。[发起方作用域](2026-07-15-agent-initiator-scope.md)与[Session 准备](2026-08-05-session-preparation.md)同样保留独立的生命周期依据。

## 验证

注册表测试覆盖原子获取、重复及修改后的选择、独立操作、在线与重叠归属、失败、取消、发起方归属和 teardown 等待。真实工厂测试把恢复保持在未发布 setup 中，获取离线归属，并验证发布拒绝、回滚及成功重试。真实 Git 工具测试在提交和合并预检结果被保持期间引入竞争激活和审查。Loader 回放通过 Host 读取、真实恢复工厂和模型可见的工具拒绝验证竞争，释放后成功恢复，同时保留集成 transcript（文本记录）和冷投影。
