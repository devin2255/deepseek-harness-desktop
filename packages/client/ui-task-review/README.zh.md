# @deepseek-ai/dsh-client-ui-task-review

[English](README.md) | 中文

独立 Task 审查工作区的参考文档。插件占用 `shell.review`，并消费客户端运行时的当前审查投影。它展示变更文件、受限的统一 Diff、分支与基准信息、验收条件、验证证据引用、未解决风险和持久交付回执。审查数据保留在不依赖 React 的 Task 运行时中；组件通过注入 props 接收运行时可观察数据与收窄后的回调。

审查对象选择器区分根结果与通过持久 subagent 目录发现的直接子结果，包括普通 Session 列表中没有的冷态子级。打开审查会观察该目录，离开时释放观察；刷新会重新读取目录和审查数据。加载与目录失败保持可见。运行中的条目禁用，Host 还会拒绝仍驻留或未隔离的子级。子级检查禁用所有根任务交付操作，并隐藏根任务成功回执；它不会提交或集成子级。验收条件和风险仍属于所属根 Task。

刷新后，只要已选路径仍然存在，文件列表就会保留该选择。二进制和截断响应会被显式标记。Patch 文本在移除终端控制序列和非排版控制字符后按纯文本渲染；组件不解释 HTML，也不创建文件系统链接。断连时保留最后一次审查并标记为过期，重连时刷新；结构化 Host 错误保持可重试。Apply 冲突会明确说明源检出保持不变。

即使所选审查没有变更文件，集成历史仍保持可见。每次尝试展示结果、所选子级，以及经过验证的发布或冲突事实。子级检查使用同一个根级寻址选择器。未确认结果要求先检查 Git 再重试；预检冲突不代表根目录中存在冲突标记。未解决的集成冲突禁用根级 Commit 和 Apply，但允许“要求修改”。后续完成覆盖的集成会标记历史冲突，不会隐藏它。集成到根任务绝不代表已向源项目交付。

“要求修改”“创建提交”“应用到项目”和“丢弃工作树”是彼此独立的操作。每项操作都有确认步骤。Commit 说明它只改变任务工作树。Apply 说明源目录必须干净、HEAD 不得变化，并且必须通过三方预检。Discard 区分无法恢复的未提交内容与任务分支上保留的提交。操作成功后展示 Task 的持久回执，不根据本地 UI 状态推断完成。

## 模型体验

无。这个浏览器侧 Task 审查与交付界面不注册模型输入或交互响应。

#### KV Cache 影响

无；该包既不组装也不发送模型请求。

## 已知限制与暂缓事项

- 尚不支持按文件或 hunk 暂存；Commit 针对完整且精确的审查 revision。
- 验证证据展示持久 Session 与序号引用；尚不能直接跳转到对应记录。
- 尚不支持 Diff 搜索与并排视图。
- 此工作区尚不提供子级提交、批量集成和冲突解决操作。
