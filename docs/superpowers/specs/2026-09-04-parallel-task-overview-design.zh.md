# 并行任务总览设计

[English](2026-09-04-parallel-task-overview-design.md) | 中文

状态：范围和书面规格均已在对话中批准。本文定义验收要求，不代表功能已经交付。

## 范围

交付[桌面产品设计](2026-08-14-deepseek-harness-desktop-design.md)中第一个可独立使用的阶段：跨工作区查看现有根会话、运行活动和待处理的用户交互。现有会话界面继续承担执行和交互。[Mission Control 提案](../../../.agents/notes/proposed/feature/2026-08-14-desktop-agent-mission-control.md)维护更完整的产品方向。

总览不创建任务数据库、不改变 agent（智能体）执行、不自动启动 agent，也不宣称并发写入安全。应用拥有的 worktree、结果验证、变更审查、调度、原生通知和 Studio 属于其他阶段。

## 用户流程

桌面启动后进入总览。常驻的“任务”入口允许从任意会话返回，且不取消运行。侧栏和工作区导航保持可用；打开会话时，中心总览切换为现有会话界面。返回总览保留当前会话选择和草稿，不创建空白会话。

“新建任务”复用现有的工作区感知新建会话操作。没有工作区时，现有的添加工作区和模型设置流程保持可用。显式选择工作区优先于现有的当前或最近工作区回退规则。本阶段不代替用户发送提示词或更改权限。

总览按“需要处理、运行中、其他任务”的顺序对根会话分组。每行显示工作区、标题、主要状态和已知的运行中 subagent 数量。组内按现有更新时间降序排列，再按会话 id 排序；不虚构等待时长或完成时间。空组显示简洁的空状态。工作区归属读取工作区注册表，不比较路径字符串；未归属会话具有明确标签。

## 状态规则

| 条件 | 分组 | 含义 |
|---|---|---|
| 根会话或已知后代等待审批、计划审查或回答 | 需要处理 | 至少一个用户交互待处理；其他后代可能仍在运行 |
| 没有待处理交互，且根会话或已知后代正在运行 | 运行中 | 会话树中仍有执行活动 |
| 两个条件都不成立 | 其他任务 | 当前未报告活动或待处理交互；不表示成功 |
| 连接中断或列表刷新失败 | 保留上次列表并提示数据陈旧 | 同步成功前不能将活动视为当前状态 |

来源为 subagent 的行表示嵌套活动，不是独立根任务。普通 fork 保持独立行，并终止后代聚合。归档根会话和未使用的空白会话不进入总览。新建会话草稿仍通过现有会话流程访问，不显示为运行中任务。

现有 `completed` 字段只是本地未读提醒，不能决定成功完成、可审查状态或所属分组。未知结果保持未知。数量仅描述已知后代；子目录缺失或加载失败不表示没有子会话。

## 交互定位

任务行通过现有会话服务打开根会话。每个待处理交互提供独立入口，标识所属根会话或后代及交互类型。多个等待中的后代必须都可发现；任务徽标可以显示汇总数量，但不能只保留一个目标。

根交互使用普通会话导航。子交互必须使用现有的权威直接父级地址和 subagent 导航路径。目录元数据缺失时，通过目录服务解析；目标不可用时显示错误，并保持总览可用。标题和推断的父子链接不能作为继续交互的授权依据。

导航后，现有审批、计划审查或提问组件展示实际待处理请求。若请求已在导航期间结束，目标界面显示当前状态，不重新创建请求。总览自身不提交审批，也不提供批量批准、全局停止或重启操作。

## 架构

展示功能以客户端插件实现，组合到桌面配置中，使用布局拥有的导航状态和新增的中心页面 slot。保留会话 slot 及其子注册。Electron Main 和 preload 不接收任务状态，也不增加通用 API。普通 Web 组合保持不变，除非显式安装总览插件。

纯选择器从运行时会话列表镜像、工作区注册表、归档成员信息和已知后代摘要派生任务行。当前页面和视图偏好仅作为展示状态。不为渲染列表枚举会话日志、创建所有会话作用域或轮询每个会话。

连接服务提供传输健康状态；必要时通过运行时的类型化只读接口暴露会话管理器已有的列表刷新错误状态。单调变化的 `pending`/`ready` 到达阶段不足以证明数据新鲜。重新连接后，仅在新列表基线同步成功时清除数据陈旧提示；刷新失败则保留提示，并通过现有刷新机制提供重试。

所有订阅和注册遵循 Cordis 生命周期管理。切换会话、关闭总览或移除插件会释放展示订阅，但不打断运行中的 agent。本阶段不增加模型可见内容，也不改变持久会话事件格式。

## 展示与安全

复用现有主题 token、语言设置和键盘焦点规范。状态必须有文字，不能仅靠颜色表达。在支持的桌面最小宽度下，任务标题可截断并保留可访问的完整标签；主要操作和状态无需横向滚动页面即可访问。总览是可操作列表，不是图编辑器或可拖拽仪表盘。

明显提示任务在所选目录中执行，尚不提供自动 worktree 隔离。“新建任务”保持现有工作区和权限行为；总览既不默认开启并发文件写入，也不宣称防止普通会话中已经可能发生的冲突。并行验收使用彼此独立的临时目录。

## 验收

1. 两个不同工作区中的根会话并行运行且同时可见；进入任意会话再返回，不中断任何一方。
2. 根会话停止但后代仍运行时，任务仍属于“运行中”。后代等待交互时，根任务进入“需要处理”，同时保留运行中后代数量。
3. 审批、计划审查和提问入口打开正确的现有交互界面，包括后代拥有的请求及导航期间已经结束的请求。
4. 普通 fork 独立统计；归档根会话、未使用的空白会话和 subagent 行不会重复成为任务。
5. 停止的会话和未读完成提醒不会产生成功或可审查声明。
6. 首次加载、已同步空列表、首次失败、断线、刷新失败和成功重新同步具有不同且真实的展示。陈旧行不被展示为实时状态。
7. 纯选择器和组件测试覆盖分组与交互目标。无需密钥的组装应用场景记录可见流程和快照；真实 Electron 验收覆盖总览导航、并行执行、待处理交互定位和重连行为。仅有 mock 测试不满足交付验收。
8. 桌面打包包含插件及其资源。现有工作区选择、模型设置、会话创建和普通 Web 组合保留回归测试覆盖。

## 交付顺序

实现依次推进运行时状态暴露与选择器、总览导航与界面、待处理交互定位，最后完成组装快照与 Electron 验收。每一步在集成前包含针对性测试。没有实时状态或组装验收的预览只是中间成果，不代表本规格完成。
