# DeepSeek Harness Desktop Windows 安装程序设计

[English](2026-08-24-windows-installer-design.md) | 中文

状态：2026-08-24 产品设计、技术设计与书面规格均已确认。

## 决策摘要

DeepSeek Harness Desktop 以单个 Windows 引导式安装程序发布，用户可在干净的 Windows 电脑上双击安装。安装后的应用必须自包含，不得依赖源码仓库、Node.js、pnpm、包管理器存储或构建电脑上的路径。首个版本支持 Windows 10 和 Windows 11 x64。

安装程序采用 `electron-builder` 的引导式 NSIS 构建目标。它以当前用户身份安装且无需管理员权限，提供可写的默认目录和自定义目录选择，并提供已确认的桌面快捷方式、开始菜单快捷方式、登录时启动和安装后立即启动选项。

## 产品要求

发布产物是名为 `DeepSeek-Harness-Setup-<version>-x64.exe` 的单个文件。打开该文件会进入可见的安装流程，而不是启动一个未打包应用或解压便携目录。

默认安装目录为 `%LOCALAPPDATA%\Programs\DeepSeek Harness`。目录页面允许用户选择其他可写目录。安装程序必须通过可纠正的提示拒绝受保护或不可写的目标位置，不得静默请求升权。

选项页面包含以下相互独立的选择：

- 创建桌面快捷方式，默认开启。
- 创建开始菜单应用快捷方式，默认开启。
- 用户登录时启动 DeepSeek Harness，默认关闭。

完成页面包含“立即启动 DeepSeek Harness”，默认开启。无论是否选择开始菜单应用快捷方式，安装程序都必须在 Windows“已安装的应用”中注册卸载程序。

## 安装流程

引导式流程包含五个用户可见阶段：欢迎、目标目录、可选系统集成、安装进度和完成。在开始写入程序文件前，用户可返回或取消。取消或失败不得留下指向不完整安装的应用条目。

安装过程先将完整版本写入所选安装父目录下的暂存位置，校验暂存应用后才将该版本设为当前版本。替换失败时，上一完整版本必须仍可使用；若不存在可用版本，则必须明确报告。安装程序不得混用两个应用版本的文件。

应用使用稳定的 Windows App User Model ID，使任务栏分组、通知、快捷方式和后续升级始终指向同一产品身份。

## 程序与用户数据归属

程序文件仅存放在所选安装目录下。可变应用状态存放在 `%APPDATA%\DeepSeek Harness` 下；日志、设置、凭据引用、会话、运行时配置和其他生成状态不得写入程序目录。

打包后的桌面进程必须在 `%APPDATA%\DeepSeek Harness` 下显式指定 Harness 主目录。它不得从仓库、包管理器存储、构建用户主目录或开发环境的 `~/.dsh` 目录解析插件或配置。首个安装程序版本不包含从 `~/.dsh` 导入开发数据的功能，也不得隐式导入。

凭据值继续由现有凭据能力管理。安装程序不得嵌入 API 密钥、复制根目录 `.env` 或在日志中记录秘密。

## 自包含应用闭包

安装后的应用包含 Electron、渲染器资源、DeepSeek Harness 运行时、选定的桌面配置和插件、必需的 JavaScript 依赖以及必需的 Windows x64 原生模块。它必须能在离线状态下完成安装、启动并进入首次运行配置体验。

当运行时 loader 需要普通文件时，可执行 CLI 文件、Cordis 配置、Web 资源、原生模块及其他通过文件系统路径打开的资源必须打包在 ASAR 之外。Electron 支持时，主进程和渲染器代码可以保留在 ASAR 中。

出现以下任一情况时构建必须失败：打包闭包中存在指向源码仓库或包管理器存储的符号链接或目录联接、存在构建电脑的绝对路径、缺少必需的对等依赖（peer dependency）、缺少配置或 Web 资源、缺少可用的原生二进制文件，或生产进程启动器无法执行 CLI 入口。校验必须针对最终打包目录执行，不能只检查源码依赖图。

## 应用启动与就绪

双击已安装的快捷方式后，应用必须立即创建原生窗口。Harness 初始化前先显示轻量启动界面，并按实际条件展示“加载本地运行时”“校验配置”“启动本地服务”等阶段；不得为了动画设置任意固定等待时间。

只有经过认证的本地就绪探针确认预期应用版本和必需能力可用后，才加载主渲染器。本地服务仅绑定环回地址，使用临时端口或应用专用端口；仅存在进程或 TCP 端口可连接不能代表服务已就绪。

启动过程有明确的超时上限。失败后，进度界面替换为安全错误页面，其中概述失败阶段，并提供“重试”“打开日志”和“退出”操作。错误文本和日志必须遮盖凭据，不能把内部堆栈跟踪作为面向用户的主要消息。

每个用户数据目录只能由一个桌面应用实例持有。第二次启动必须聚焦已有窗口并转发受支持的启动意图，不得启动相互竞争的 Harness 服务。

## 登录时启动与快捷方式

登录时启动通过 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 为当前用户注册，并使用安全引号参数指向已安装的可执行文件。再次运行安装程序时，该值必须根据所选选项更新或移除。卸载时仅在该值属于当前安装时移除它。

桌面和开始菜单快捷方式使用已安装的可执行文件、稳定产品身份、产品图标和所选安装目录。当安装路径或可执行文件布局变化时，升级过程修复用户选择保留的快捷方式，并删除产品拥有的旧快捷方式。

## 升级行为

打开较新安装程序时，它会检测当前用户的已有安装。安装程序默认沿用原目标目录及之前的快捷方式和登录时启动选择，同时允许用户修改这些选项。

替换前，安装程序请求正在运行的应用退出，并等待其拥有的进程树停止。如果应用无法关闭，安装程序必须让用户选择重试或取消，且不得覆盖正在使用的二进制文件。用户数据保留在原位置。未来任何用户数据 schema 迁移都必须具备原子性或可恢复性，并由拥有该 schema 的组件负责。

降级和同版本重装是显式状态，不能被当作意外升级。同版本可以允许修复安装；当已存储数据可能比目标运行时更新时，降级前必须发出警告。

## 卸载行为

卸载会移除程序文件、产品拥有的快捷方式、产品拥有的登录时启动注册项和“已安装的应用”条目。默认保留 `%APPDATA%\DeepSeek Harness`，使重新安装不会丢失设置、凭据引用、会话或日志。

卸载程序提供独立的“删除用户数据”选项，该选项默认关闭并显示准确的数据目录。选择后还需要显式确认。删除范围仅限解析后的产品数据目录；如果发现目录联接、符号链接、非预期路径解析结果，或路径位于预期 `%APPDATA%` 产品根目录之外，则必须停止删除并保留数据。

## 签名与 Windows 信誉

首个测试版本可以不签名，因此发布说明和下载页面必须解释可能出现的 Microsoft Defender SmartScreen 警告。构建配置提供签名钩子，但本地构建无需证书。正式公开发布前，发布负责人必须对签名作出明确决定。

安装程序和应用元数据使用统一的发布者名称、产品名称、图标集、可执行文件名、版本和升级身份。未来的签名流水线先签署应用可执行文件，再签署外层安装程序，并在打包后验证签名。

## 验证策略

单元测试覆盖安装选项映射、路径解析、归属检查、启动参数、就绪状态转换、超时恢复和遮盖敏感信息。静态打包校验针对最终产物检查依赖闭包、可执行资源、原生模块、禁止的链接和构建电脑路径。

Windows x64 自动化测试从干净用户配置开始，验证默认目录和自定义目录的引导式安装、每个快捷方式选项、登录时启动注册、立即启动、首次运行就绪，以及在没有 Node.js、pnpm、仓库、包管理器存储或网络连接时的运行能力。

升级测试先安装旧产物并创建有代表性的用户状态，再运行新安装程序，验证进程停止、选项保留、完整版本替换和用户数据保留。卸载测试覆盖保留数据和显式删除数据，并验证不安全重定向路径会被拒绝。回归覆盖已有开发配置和损坏的打包配置，确保两者都不会导致静默无窗口失败。

Windows CI 构建安装程序并将其发布为带版本的产物。发布验证记录产物校验和、安装后版本、测试所用 Windows 镜像及产物是否签名。

## 范围

本版本包含 Windows x64 引导式安装程序、目标目录选择、桌面和开始菜单快捷方式、可选登录时启动、完成页启动、升级基础、卸载数据选项、自包含依赖闭包、原生启动与恢复界面、安装程序自动化测试、双语文档、实现对应的 Agent Note 和 CI 安装程序产物。

本版本不包含 Windows ARM64、macOS、Linux、应用内自动更新、购买或运营代码签名证书、MSI 或企业部署策略、崩溃报告服务、从开发环境 `~/.dsh` 隐式迁移数据以及最终品牌视觉资源。

## 验收条件

当非开发者能在干净且受支持的 Windows x64 电脑上下载一个 EXE，选择安装目录和系统集成，无需管理员权限或网络即可完成安装，并看到能进入首次运行设置或可恢复错误页面的响应式 DeepSeek Harness 窗口时，即满足本安装程序设计。同一产物还必须以可预期方式升级和卸载，默认保留用户数据，仅在显式且安全的确认后删除数据，并且不包含对构建环境的运行时依赖。
